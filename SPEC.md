# Dislocation — ТЗ (MVP)

Telegram-бот для отслеживания вагонов в пути по накладной: общее расстояние,
оставшееся расстояние, срок доставки, опережение/отставание, интерактивная карта маршрута.

Статус: проектирование. Кода нет.

## 1. Область MVP

- Только сеть РЖД (РФ).
- Только повагонные отправки.
- Одна накладная = одна единица отслеживания (несколько вагонов по накладной едут вместе, номера вагонов в MVP не храним).
- Текущая станция дислокации вводится вручную.
- Интерфейс: только Telegram-бот + Mini App с картой. Отдельной веб-админки нет.

## 2. Данные накладной

| Поле | Обязательно | Пример |
|---|---|---|
| Номер накладной | да | ЭА000001 |
| Станция отправления (код ЕСР) | да | 190205 Серпухов |
| Станция назначения (код ЕСР) | да | 946002 Досатуй |
| Дата/время приёма к перевозке | да | 24.09.2026 17:43 МСК |
| Срок доставки истекает (дата) | да | 25.10.2026 |
| Статус | авто | в пути / прибыл |

Срок доставки вводится датой «истекает» из накладной (уже с учётом продлений),
количество суток бот считает сам для отображения.

## 3. Сценарии бота

**Новая накладная** — пошаговый ввод полей. Станции выбираются через поиск
по названию или коду ЕСР, выдача топ-5 кнопками.

**Отследить**:
1. Если активных накладных несколько — выбор из списка.
2. Ввод текущей станции операции (поиск, топ-5 кнопками).
3. Ввод даты/времени операции (по умолчанию «сейчас»).
4. Ответ бота (см. раздел 4).

Каждый ввод дислокации сохраняется в историю.

**Закрыть накладную** — перевод в статус «прибыл».

**Доступ** — только белый список Telegram ID.

## 4. Ответ «Отследить»

Текст:
- номер накладной, маршрут (отправление → назначение), текущая станция и время операции;
- всего / пройдено / осталось, км (тарифные);
- срок по накладной (дата и сутки);
- прогноз прибытия и «опережаем / отстаём на N сут».

Кнопка «Открыть карту» — Mini App (раздел 6).

## 5. Расчёты

**Расстояния** — по графу сети, построенному из Тарифного руководства №4, книга 1
(участковые таблицы: станции в географическом порядке с километражем).
Кратчайший путь по графу даёт полный список станций маршрута.
- Всего = путь (отправление → назначение).
- Осталось = путь (текущая станция → назначение).
- Пройдено = всего − осталось.
- Контроль: сверка с расстояниями из реальных накладных (раздел 8).

**Правила построения графа** (проверены прототипом 05.10.2026):
1. Берутся только листы российских дорог — с пометкой «(Р)» в имени листа.
2. Каждый участок в кн. 1 помечен типом в заголовке. Встречаются: «Основной тарифный
   участок», «Соединительная линия», «Малодеятельный», «Линии Московского узла»,
   «Линии Санкт-Петербургского узла», «Для пассажирского движения», «Строящиеся линии»,
   «Для местного сообщения».
3. Транзит — только по основным тарифным участкам.
4. Участки остальных типов используются только как первое/последнее плечо: если станция
   отправления или назначения стоит на таком участке, путь идёт от неё до ближайшего
   узла транзитного графа по её участку.
5. Стыки дорог: конечная станция участка может не быть перечислена в его таблице
   (она на соседней дороге). Её берём из шапки «до ст. …», длину — как сумму двух
   км-колонок любой строки.
6. Тёзки: одноимённые станции в разных частях сети. При разрешении конца участка
   по названию выбирается станция с кодом ЕСР, ближайшим к кодам самого участка.
7. Очистка: коды вида «946002 .» → 946002, км вида « 169  км » → 169.

**Известные расхождения** — граф получается короче ЭТРАН (никогда не длиннее):
тариф избегает части коротких ходов, не размеченных в кн. 1 особым типом.
Пример: Тобольск → Афипская, граф срезает через Курумоч — Жигулёвское Море на Сызрань.
ТР4 кн. 3 для сверки не используется: в ней есть непонятные значения
(например, Бологое → Чудово 752 км). Для MVP принимается как погрешность.

**Прогноз и опережение/отставание**:
- средняя скорость = пройдено / (время операции − время приёма), км/сут;
- прогноз прибытия = время операции + осталось / средняя скорость;
- сравнение прогноза с датой «срок истекает».
- При малом пройденном пути (порог уточнить, ориентир 20%) прогноз помечается как неточный.

Ограничение: «осталось» считается по кратчайшему пути, а не по плану формирования.
При обходных маршрутах значения приблизительные.

## 6. Карта (Telegram Mini App)

- Leaflet + подложка OpenStreetMap (бесплатно, без ключа). Подложка заменяема.
- Слои: весь маршрут серым по станциям, пройденная часть цветом,
  точки истории дислокаций, маркеры отправления/назначения/текущей станции.
- Координаты станций — из справочника `phone_number_railstation` (поля lat/lon);
  покрытие проверить, недостающие дополнить (OSM / вручную).
- Хостинг: VPS, HTTPS, домен (duckdns).
- Доступ: только из Telegram, проверка подписи `initData`.
- Закрыто от индексации: robots.txt disallow-all + заголовок X-Robots-Tag: noindex.

Отклонённые варианты: Яндекс JS API (бесплатно запрещено для мониторинга
транспорта и закрытых систем), публичные тайлы OpenRailwayMap (только для публичных
приложений без регистрации). 2ГИС — возможный платный вариант на будущее.

## 7. Данные и источники

- Справочник станций: импорт из `D:\PROJECT\phone_number_railstation` (таблицы
  stations, station_aliases, railways). Поиск — pg_trgm по нормализованному названию + код ЕСР.
- Сеть и расстояния: ТР4, страница https://www.sovetgt.org/index.php?link=65.
  Книги 1, 2, 3 лежат отдельными файлами .xls, прямые ссылки вида
  `https://sovetgt.org/tr4/ГГГГ/ММ/ДД/Kniga_1_ГГГГ-ММ-ДД.xls`. Архив по месяцам:
  https://sovetgt.org/tr4/. Обновляется примерно раз в месяц, граф пересобирается после обновления.
  Кн. 1 — 43 листа (по дороге на лист), около 1200 участков по РФ, около 13 тыс. станций.
  Коды ЕСР в кн. 1 шестизначные; в справочнике станций ключ пятизначный
  (`station_code`), полный код — `station_code_full`.
- Проект отдельный, со своей БД (PostgreSQL). Справочник станций импортируется
  один раз, дальше проекты друг от друга не зависят.
- Координаты станций без lat/lon интерполируются по километражу между ближайшими
  станциями маршрута с координатами. Проверка 05.10.2026: на 4 эталонных маршрутах
  97% станций есть в справочнике, у 78% есть координаты.

## 7.1. Стек и окружение

- Python, aiogram (бот), FastAPI (API для Mini App), PostgreSQL, pytest.
- Локально: PostgreSQL в Docker, приложение — из venv.
- Продакшен (VPS): всё в Docker Compose (Postgres + бот + API + HTTPS-прокси).
- Деплой: правки локально → git push → git pull на сервере. Код на сервере не правится.
